# Database

21 tables. PostgreSQL in production, SQLite for local development and the test
suite — the same migrations run on both.

## Identity

| Table | Purpose |
|---|---|
| `users` | Internal id ↔ Discord id. The only place they are linked. |
| `guild_memberships` | Which servers a user has interacted in (powers the DM server picker) |
| `anon_aliases` | Public identities. Partial unique index enforces one *current* alias per user per guild. |
| `agreements` | Rules acceptance, per user per guild per version |

## Guild configuration

`guilds`, `guild_settings` — channels, moderator roles, feature toggles,
character limit, rotation period, rules version.

## Content

| Table | Notes |
|---|---|
| `confessions` | Dual ids: random `id` plus per-guild sequential `public_number`. Parent/root columns form update chains. |
| `ratings` | Unique on (confession, voter) — changing a rating updates the row |
| `bookmarks` | Private to each user |
| `follows` | Targets an **alias**, not a user, so rotation breaks the link |
| `polls`, `poll_options`, `poll_votes` | One poll per confession; unique vote per user |

## Moderation

`reports`, `warnings`, `bans`, `moderation_ledger` (append-only).

## Operations

`notifications` (the delivery queue and the closed-DM guarantee), `drafts`,
`export_records`, `system_events`.

## Design decisions worth knowing

**Enums are `VARCHAR` + `CHECK`, not native Postgres enums.** Adding a value is
an ordinary migration rather than a lock-taking `ALTER TYPE`.

**No separate `confession_links` table.** The parent/root columns on
`confessions` express the same relationships without a second source of truth
that could drift.

**Follows, ratings and reports key on internal user ids, not Discord ids.** One
consistent internal identity everywhere means a leak has fewer places to happen.

**Confessions are soft-deleted.** `is_deleted` hides them everywhere; the row
survives for moderation history.

## Migrations

```bash
alembic upgrade head                     # apply
alembic revision --autogenerate -m "..." # create after changing models
alembic downgrade -1                     # roll back one
alembic current                          # what is applied
```

Batch mode is enabled for SQLite so `ALTER TABLE` works there too. Always read
an autogenerated migration before applying it.
